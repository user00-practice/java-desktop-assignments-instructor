# 解答例（講師専用）

10テーマすべての解答例と、その自動テスト（JUnit 5）です。各テーマの「必須要件」と「実装上の条件」をすべて満たしています。「拡張要件」は実装していません。このフォルダは受講者用リポジトリには同期されません。

## 開き方

1. IntelliJ IDEA のメニュー「ファイル」→「開く...」で、この `answer` フォルダを選ぶ（リポジトリ全体ではなく `answer` フォルダを開く）
2. 「プロジェクトを信頼」を押す
3. JDK 25 が設定されていなければ、メニュー「ファイル」→「プロジェクト構造...」→「プロジェクト」で設定する
4. 実行構成の一覧から「解答例 テーマ01 じゃんけん」などを選んで実行する

受講者用のスターターと同じパッケージ名・クラス名を使っているため、別のプロジェクトとして開く構成にしています。

## 受講者への公開

このフォルダの中身は、Actions タブの「解答例リポジトリへ公開」を手動で実行したときだけ、解答例リポジトリへ送られます（手順は SETUP.md の後半）。その際、この README.md は送られず、受講者向けに書いた `PUBLIC_README.md` が README.md になります。`PUBLIC_README.md` 以外のファイル（ソースコードのコメントなど）には、「講師専用」「指導のポイント」といった講師向けの記述を書かないでください。公開時の安全チェックで止まります。

## テーマごとのクラス構成と指導のポイント

| テーマ | 追加したクラス | 指導のポイント |
| --- | --- | --- |
| 1 じゃんけん | `Hand`（enum）、`Result`（enum）、`Round`（record） | 勝敗判定は「自分の手が勝てる相手の手」を switch式で決め、一致するかで判定。9通りの if 文を書かせないのがねらい |
| 2 数当て | `GameState`（enum）、`Hint`（enum） | `parseInt` の例外処理と範囲チェックを画面側、判定と回数管理を `NumberGuessGame` 側に分けている |
| 3 電卓 | `Operator`（enum） | 計算の状態（直前の数・演算子・次の入力を新しく始めるか）を `Calculator` に持たせる。0除算は `ArithmeticException` で知らせる |
| 4 ポモドーロ | `Mode`（enum） | `Thread.sleep` ではなく `javax.swing.Timer` を使う理由（画面が固まらない）を説明する。動作確認は `Mode` の秒数を10秒などに書き換える |
| 5 クイズ | `Question`（record） | 出題画面と結果画面を `CardLayout` で切り替え。ファイルが無い場合と形式が違う場合で、別々の例外を受け取っている |
| 6 ToDo | `Todo`（record） | record は値を変えられないので、完了の切り替えは `toggle()` で新しい record を作って置き換える |
| 7 メモ帳 | なし | ×ボタンで確認するために `DO_NOTHING_ON_CLOSE` と `WindowListener` を使う。`setText` でも `DocumentListener` が反応する点に注意 |
| 8 三目並べ | `Mark`（enum） | 盤面は `Mark[3][3]`。ラムダ式の中でループ変数を使うには、別の変数（`int r = row;`）に入れ直す必要がある |
| 9 家計簿 | `EntryType`（enum）、`Entry`（record） | 集計は Stream の `filter`・`mapToInt`・`groupingBy`。enum を `Type` という名前にすると `java.awt.Window.Type` と衝突する |
| 10 お絵描き | `Shape`（sealed interface）、`Line`・`Rect`・`Oval`（record）、`ShapeType`（enum） | パターンマッチングの switch に default が要らないこと、case を書き忘れるとコンパイルエラーになることを実際に見せる |

## 仕様の解釈で決めたこと

- テーマ3：「1 ＋ 2 × 3 ＝」は仕様どおり左から順に計算して9にしています（掛け算を先にする電卓ではありません）
- テーマ7：文字数は改行を除いて数えています
- テーマ8：決着後は空きマスだけを押せなくしています。印のあるマスまで無効にすると文字が灰色になり見にくいためです（押しても何も起きません）
- テーマ9：メモの中のカンマはCSVが崩れるため「、」に置き換えて保存しています
- テーマ10：ドラッグせずにクリックしただけのときは、図形を追加しません

| 1 じゃんけん | `JankenGameTest`、`HandTest` | 15 | 9通りの勝敗、通算成績、リセット、同じシードなら同じ手の順番 |
| 2 数当て | `NumberGuessGameTest` | 8 | ヒント、範囲チェック、10回で失敗、10回目の正解、履歴 |

### テストの実行方法

1. `answer` フォルダをIntelliJで開く（JUnit 5 のライブラリは、初回に自動でダウンロードされます）
2. 実行構成の一覧から「テスト テーマ01 じゃんけん」などを選んで▶を押す。全テーマまとめて実行する場合は「テスト 全テーマ」を選ぶ
3. 下に表示される実行結果で、すべて緑のチェックになっていることを確認する

実行構成を使わずに、各テーマの `test` フォルダを右クリックしてテストを実行することもできます。

ライブラリのダウンロードが始まらず、テストの `import org.junit...` が赤くなる場合は、メニュー「ファイル」→「プロジェクト構造...」→「ライブラリ」で `junit.jupiter` を選び、表示される修正（ダウンロード）を実行してください。

### テストのために解答例を変えた点

テーマ1の `JankenGame` に、`Random` を外から渡せるコンストラクタ `JankenGame(Random random)` を追加しました。シード（種）を決めた `Random` を渡すと、コンピュータの手の順番を固定できるので、`play` の結果を確かめられます。引数なしのコンストラクタは今までどおり使えます。

### テストの使いどころ

- **採点の補助**：受講者のコードは設計が自由なのでこのテストをそのまま当てることはできませんが、「どんな入力で何を確かめるか」は受け入れ確認の観点としてそのまま使えます。
- **授業の題材**：電卓の `CalculatorTest` は、ボタン操作を文字列で書いて結果を確かめる形なので、テストの考え方を説明する例として使いやすいです。

教材作成時に、上記の自動テスト118件がすべて成功すること（JUnit 5.9で実行）と、すべての画面が表示されることを確認しています。ただし作成環境のJDKは21のため、Java 25 での実行確認は配布前に講師の環境で行ってください。
